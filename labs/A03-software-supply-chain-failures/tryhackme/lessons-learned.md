# Lessons Learned — Local Unverified Library Supply Chain Failure

## What Was Found

| Finding | Severity |
| --- | --- |
| Local unverified library imported into runtime | High |
| Import path manipulated to prioritize local `lib` code | High |
| Missing dependency inventory and integrity controls | High |
| Debug helper exposed through public API input | High |
| Flask debug mode enabled on exposed service | High |

---

## 1. Local Libraries Are Supply Chain Inputs

A local `lib` directory can feel safer than a package registry because it sits inside the project tree. It is still part of the software supply chain. If the code was copied from another source, generated by a third party, downloaded during a lab, or maintained outside normal review, it needs provenance, ownership, and integrity controls.

## 2. Import Order Is a Security Boundary

The line below changes which code Python trusts first:

```python
sys.path.insert(0, os.path.join(os.path.dirname(__file__), 'lib'))
```

That makes local files take precedence over normal package resolution. If an attacker or compromised build step can write to that location, the application may import malicious code under a legitimate-looking module name.

## 3. Debug Helpers Do Not Belong in Public Routes

The debug trigger was simple:

```python
if data == 'debug':
    return jsonify(debug_info())
```

This pattern turns diagnostic internals into externally reachable behavior. Debug output should go to protected logs or authenticated admin tools, not to unauthenticated API clients.

## 4. A03 Often Overlaps With A02

The primary issue is A03 because the trusted code boundary failed. A02 also applies because debug mode and public diagnostic behavior are insecure configuration choices. In practice, both have to be fixed: harden dependency management and harden deployment settings.

## 5. Checklist for Future Supply Chain Labs

```text
Recon
[ ] Identify exposed services and framework banners
[ ] Check whether development servers or debug modes are exposed

Source Review
[ ] Find imports from local lib/vendor/third_party paths
[ ] Search for sys.path changes and PYTHONPATH dependence
[ ] Identify package manifests, lockfiles, and SBOMs

Dependency Controls
[ ] Confirm package origin and ownership
[ ] Confirm versions are pinned
[ ] Confirm hashes or signatures are verified
[ ] Run dependency vulnerability scanning

Runtime Testing
[ ] Test debug or diagnostic inputs
[ ] Confirm errors do not expose dependency internals
[ ] Capture screenshots and redact secrets or flags
```
