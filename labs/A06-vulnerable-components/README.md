# A06: Vulnerable Components

## Objective

Identify risks from outdated, unsupported, or vulnerable dependencies and components.

## Scope

- Platform:
- Lab or room:
- Target component:
- Version:

## Key Concepts

- Known CVEs
- Unsupported libraries
- Outdated frameworks
- Dependency confusion
- Missing software inventory

## Tools

- Dependency manifests
- npm audit or equivalent
- pip-audit or equivalent
- osv-scanner
- Public vulnerability databases

## Workflow

1. Inventory components and versions.
2. Identify known vulnerabilities.
3. Validate exploitability in the lab scope.
4. Capture evidence in `screenshots/`.
5. Record findings and remediation.

## Checklist

- [ ] Components inventoried
- [ ] Versions identified
- [ ] Vulnerabilities researched
- [ ] Screenshots captured
- [ ] Remediation written
